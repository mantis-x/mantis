## Current Architecture

Multi-chain signal-detection + execution pipeline, monorepo under `packages/`:

- **`packages/ingestion`** — `ChainCollector` polls EVM chains via `web3.py`, `EventNormaliser` (`src/decoders/event_normaliser.py`) decodes raw logs into `NormalisedEvent`s, `PriceOracle` prices them. Chain configs live in `src/chains.py` (`ALL_CHAINS` registry: `mantle`, `arbitrum`, `hashkey`, `ethereum` — Ethereum added 2026-07-18, see Completed Work). Enabled chains selected via `CHAINS` env var.
- **`packages/detection`** — `detector.py` runs z-score anomaly detection per pool, seeded with synthetic baseline history (`_build_synthetic_history()`). Per-chain thresholds via `ZSCORE_THRESHOLD` / `ZSCORE_THRESHOLD_ARBITRUM` (any `ZSCORE_THRESHOLD_<CHAIN>` works generically, incl. Ethereum).
- **`packages/enrichment`** — `Enricher` (`src/enricher.py`) calls the Claude API (`claude-sonnet-5` as of the latest fix) to classify anomaly candidates into `Signal` objects. Stateless, retry logic in `_call_claude()`.
- **`packages/executor`** — trade execution. `arbitrum/swap_executor.py` executes via Uniswap V3 SwapRouter02 + QuoterV2, with real slippage protection, live Chainlink ETH/USD pricing, gas-price buffering for Arbitrum's fast base-fee drift, and a position-cap guard checked against real wallet balance. `identity/erc8004_logger.py` logs execution/agent-identity to chain — routes per origin chain (mantle/arbitrum/hashkey/ethereum), fixed 2026-07-11 (see Completed Work). `_do_swap`/`_wallet_balance_usd` now raise explicitly for any chain without a real executor (fixed 2026-07-18) instead of silently falling through to the Mantle path — closes a gap that existed for HashKey and would have silently extended to Ethereum.
- **`packages/delivery`** — fans out signals to Telegram/Discord/LINE bots. `audit/on_chain_logger.py` also routes per origin chain (same fix, same session). `/verify <id>` now resolves the signal's actual chain instead of hardcoding Mantle (fixed 2026-07-18 — see Completed Work); signal cards and `/history` now show the numeric ID so `/verify` actually has something to look up (that gap predated the fix).
- **`packages/shared`** — SQLAlchemy models + Alembic migrations (Postgres). `AgentRegistry`, subscription management, 5 tables total.
- **`contracts/`** — Hardhat project. `SignalAuditLog.sol` + `AgentIdentity.sol` now deployed on **every chain's mainnet**, all four: Mantle (2026-07-16), Arbitrum (2026-07-16 — addresses do NOT match the other chains' shared default, requires `ARBITRUM_AUDIT_CONTRACT_ADDRESS`/`ARBITRUM_AGENT_IDENTITY_CONTRACT_ADDRESS` overrides, already set on Railway), HashKey (2026-07-11), and Ethereum (2026-07-18 — same address-divergence situation as Arbitrum, requires `ETHEREUM_AUDIT_CONTRACT_ADDRESS`/`ETHEREUM_AGENT_IDENTITY_CONTRACT_ADDRESS` overrides, already set on Railway; see Completed Work). Testnets also live on Mantle Sepolia and Arbitrum Sepolia.
- **Deploy**: Docker multi-stage build, `supervisord` runs 6 workers (ingestion, detection, enrichment, delivery, tracking, executor). `docker-entrypoint.sh` waits for Postgres then runs `alembic upgrade head` before `exec supervisord` — auto-migration wiring, verified end-to-end against a fresh Postgres container.
- **Hosting**: Railway (multi-service, Postgres + Redis + workers). This is the actual ongoing cost driver — Claude API and gas costs are both near-zero by comparison (see below).

    - **Structural confidence ceiling found, not a bug**: `detector.py`'s streaming `_process()` always calls `WalletClusterer._solo_cluster()` (one event at a time), never the real batch `cluster()` method that groups multiple wallets — so every candidate is a single-wallet cluster. The enrichment prompt's own calibration table caps single-wallet signals at 55-69 confidence regardless of z-score/volume magnitude, and in practice the model was landing at exactly 58 across 4 consecutive real+synthetic test signals — just under the default subscriber `min_confidence=60`. Real multi-wallet clustering would let genuinely coordinated activity score 70+; not implemented as of this writing. Interim fix: lowered the one known subscriber's `min_confidence` to 50 directly via `UPDATE subscriptions` (matches the enrichment-level `MIN_CONFIDENCE_SCORE` env default, so nothing that already clears enrichment gets filtered downstream).
